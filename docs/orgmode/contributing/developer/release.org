* Release Process

The package version is the seams-core version it binds. A release here
happens after seams-core has tagged =vX.Y.Z=. The tag on this repository
is the same string. Publishing is the fortran-lang fpm registry, from
=packaging/fpm/registry.toml=, or =fpm publish= once that registry
accepts uploads for the package.

Run the commands below from a clean clone. =towncrier build --draft=,
=cog bump --dry-run=, =cog check= and the package build are the checks.
Pushing the tag and opening the registry pull request are the
publishing steps and are not part of a dry run.

** From a clean clone

#+begin_src bash
git clone https://github.com/d-SEAMS/dseams-fortran.git
cd dseams-fortran
git clone --branch vX.Y.Z https://github.com/d-SEAMS/seams-core.git ../seams-core
(cd ../seams-core && meson setup bbdir --prefix="$PWD/../seams-prefix" --libdir=lib \
  -Dwith_tests=false && ninja -C bbdir && meson install -C bbdir)
export PREFIX="$PWD/../seams-prefix"
export FPM_LDFLAGS="-L$PREFIX/lib -Wl,-rpath,$PREFIX/lib"
export LD_LIBRARY_PATH="$PREFIX/lib"
export PKG_CONFIG_PATH="$PREFIX/lib/pkgconfig"
export OMP_NUM_THREADS=1
fpm test
meson setup build/meson -Dseams_libdir="$PREFIX/lib"
meson test -C build/meson --print-errorlogs
#+end_src

To exercise PDB, GRO and CON in that test, configure seams-core with
=-Dwith_chemfiles=enabled -Dwith_readcon=enabled= and export
=DSEAMS_REQUIRE_READERS=1= before =fpm test=. Chemfiles needs CMake when
it is vendored. readcon-core needs rustc 1.88 or newer. Leaving both on
=auto= is the build a user gets: a missing library stays missing and the
readers test skips that format.

** Tooling

- Cocogitto 7 or newer. The binary is =cog=. =cog.toml= sets
  =tag_prefix = "v"= and =disable_changelog = true=.
- Towncrier. =towncrier.toml= reads =changelog.d/=.
- cogapp, invoked as =python3 -m cogapp= so it is not confused with =cog=.
- fpm and meson, for the package build.

** Changelog fragments

One file in =changelog.d/= per user-visible change, named
=<issue>.<type>.md= or =+<slug>.<type>.md=. =<type>= is =added=,
=changed=, =deprecated=, =removed=, =fixed= or =security=. Present tense,
one or two sentences, about what a user of the package sees.
=changelog.d/README.md= is the same rule.

Preview the notes without writing =CHANGELOG.md=:

#+begin_src bash
towncrier build --draft --version X.Y.Z
#+end_src

** Commit check

Commits since the previous tag use Conventional Commits.
=cog check= ignores merge commits. There is no =--from= flag; pass the
range:

#+begin_src bash
cog check --ignore-merge-commits vPREV..HEAD
#+end_src

** Version copies

=fpm.toml= holds the version. The bump hook runs, in order:

1. =python3 ci/version/dseams_version.py sync X.Y.Z=, which rewrites the
   =version = "..."= line of =fpm.toml= and the =version:= line of
   =ford.md=. FORD treats a comment in the project-file front matter as
   the end of that front matter, so =ford.md= is not a cogapp copy.
2. =python3 -m cogapp -I ci/version -r @ci/version/files.txt=, which
   rewrites =meson.build=, =CITATION.cff=, =docs/conf.py= and
   =towncrier.toml=.
3. =towncrier build --yes --version X.Y.Z=, which folds =changelog.d/=
   into =CHANGELOG.md= and deletes the fragments.

Check the copies without writing them:

#+begin_src bash
python3 -m cogapp -I ci/version --check @ci/version/files.txt
#+end_src

In the same release commit, update the prose that names the tag. cogapp
does not rewrite these, because they are sentences or a list of older
tags:

- =SEAMS_CORE_REF= (and the comment above it) in =.github/workflows/ci.yml=
- =README.md=, =llms.txt=, =docs/getting-started/=, =docs/index.rst=,
  =docs/development/index.rst=, =docs/api/fortran.md=,
  =docs/user-guide/=
- the commented tag in =examples/downstream/fpm.toml=
- a new stanza in =packaging/fpm/registry.toml=, leaving every older
  tag in place

** Preparing a release (maintainer)

On =main=, with a clean tree, the fragments in place and the prose pins
updated:

#+begin_src bash
cog bump --dry-run --version X.Y.Z
cog bump --version X.Y.Z
#+end_src

=--dry-run= prints the tag it would create and does not run the hooks
and does not commit. The real =cog bump= runs the hooks, commits, and
tags =vX.Y.Z=. It does not push.

Wait for CI on that commit. The =test= job and the =readers= job both
have to pass. Do not weaken either one to get there.

** Pre-release / RC tags

=cog bump --version X.Y.Z-rc.1= creates =vX.Y.Z-rc.1=. Do not send a
pre-release tag to the fpm registry. The registry stanza is for the
stable tag only.

** Version policy

The number matches the seams-core tag this commit binds. A seams-core
patch that changes =seams.h= is a new binding and a new pair of tags. A
documentation-only change on this repository waits and rides the next
seams-core tag rather than inventing a version the engine does not have.

** Emergency / hotfixes

A fix that cannot wait for the next seams-core tag still uses the next
patch version only when seams-core has tagged it. Change the pin first,
then follow the steps above. There is no second version sequence.

** Local checks before bump

#+begin_src bash
towncrier build --draft --version X.Y.Z
cog check --ignore-merge-commits vPREV..HEAD
cog bump --dry-run --version X.Y.Z
python3 -m cogapp -I ci/version --check @ci/version/files.txt
fpm build
meson setup build/meson -Dseams_libdir="$PREFIX/lib"
meson compile -C build/meson
fpm test
meson test -C build/meson --print-errorlogs
ford ford.md
python3 docs/check_api_coverage.py build/ford
sphinx-build -W -b html docs build/html
#+end_src

** Publishing

This is the part a dry run does not do.

1. Push the version commit and the tag: =git push origin main= and
   =git push origin vX.Y.Z=.
2. Open a pull request on fortran-lang/fpm-registry whose patch is the
   stanza in =packaging/fpm/registry.toml=. The tag has to exist first.
3. Where the registry accepts an upload, =fpm publish= from a clean
   checkout of the tag. =fpm publish --show-upload-data= only prints the
   manifest; it is safe to run before the tag is public.

** After the tag

CI on the tag runs the same tests as a pull request. The docs job
deploys the manual on a push to =main=. Confirm the registry entry
resolves =dseams = "X.Y.Z"= and that
=examples/downstream/fpm.toml= still documents that tag.
