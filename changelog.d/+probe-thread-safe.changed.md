`has_chemfiles` and `has_readcon` each run their probe behind an in-process once-guard and cache the answer. Every caller but the one that runs the probe now blocks until it finishes, so concurrent calls from different threads never race; the earlier cache was a plain module-level pair with no ordering guarantee between its two writes. The guard is a small C11 `<stdatomic.h>` compare-and-swap (`src/dseams_once.c`), with no lock file and no OS-specific static initializer to get wrong; see `docs/orgmode/contributing/developer/faq.org` for the two approaches (`pthread_once`, then an exclusive `flock(2)`) this replaced and why.
